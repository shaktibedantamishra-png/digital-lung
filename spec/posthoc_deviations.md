# Deviations from posthoc_addendum_v1.md (logged as they occurred)
- PD1 (A2, before any null result was computed): the addendum wrote the PEEP-noise null as PEEP_true = PEEP_obs − u. That is Berkson error and produces no slope attenuation, so it would not test the stated mechanism. It was implemented as classical error instead: the response was generated from the observed PEEP, and the regressor was PEEP_obs + u. Phenotype eligibility (bins, levels, span) was fixed from the observed data so that it is identical across replicates.
- PD2 (A2, added after the primary null results): a noise-only null was run on the set-PEEP data (MIMIC-IV, HiRID). It is the like-for-like comparator for A2b. It was added because the A2 null with estimated PEEP noise matched the observed shares. This is disclosed as data-driven.
- PD3 (A1a): lag strata other than 0 min contain too few eligible stays in MIMIC-IV and eICU-CRD to be interpretable (≤69). They are reported, but not interpreted.
- PD4 (requested by the authors after the v15 results, before computing it): "no-intrinsic-PEEP" analysis. MIMIC-IV and HiRID; restricted to stays in which every event with set PEEP available (as-of ≤60 min) has |total − set PEEP| ≤0.5 cmH2O; stays with any primary event lacking set PEEP are excluded. Phenotype with set PEEP as predictor; noise-only null (200 replicates) using that subset's own pooled replicate Pplat SD. If its excess over null holds, it replaces the set-PEEP result as the headline evidence.
- PD5 (requested by the authors): eICU-CRD PEEP-field provenance check. If the harmonised "PEEP total" is set PEEP, the eICU null with zero PEEP error becomes the primary eICU null.
- PD5 resolved (7 Oct 2026): owner query of the source eICU-CRD respiratoryCharting table showed 'PEEP' (1464808 rows) and 'PEEP/CPAP' (126638 rows) both in respcharttypecat respFlowSettings; the only other PEEP-labelled items are care-data notes ('PS above PEEP', 'Unable to Obtain PEEPi and Vtrap'). The harmonised eICU-CRD 'peep_total' is therefore set PEEP. As pre-stated in PD5, the noise-only null (excess 13.1 points) is the primary eICU-CRD comparator; PEEP-error null variants are dropped for eICU-CRD. The SUPER-ICU variable name 'peep_total' is a misnomer for eICU-CRD.
- PD6 (requested 18 Oct 2026, after v17): hysteresis rerun with set PEEP (MIMIC-IV, HiRID; plus no-intrinsic-PEEP subset); compliance recomputed with set PEEP; stay-bootstrap 95% CI (2000 resamples) for excess over the noise-only null (per-stay null probability from 200 replicates, seed 20261007; point estimates differ from earlier runs by <=0.3 points through Monte Carlo variation).
- PD7 (requested 18 Oct 2026): joint engine sensitivity, 500 Latin-hypercube draws over r 0.1-0.5, sigma 3-8, kappa 0.33-0.95, R_aw 5-15, VD 1.5-3.0, eps* 1.5-2.0 (seed 20261007), pooled population.
- PD6 reproduced exactly with full outputs (seed 20261007, 200 replicates) and adopted as canonical for the set-PEEP, no-intrinsic-PEEP and eICU-CRD excess values; supersedes PD4 values (differences <=0.3 points, Monte Carlo).
- PD8 (18 Oct 2026, after PD6): hysteresis with set PEEP restricted to events with set-PEEP lag <=5 min, added because the HiRID set-PEEP estimate (-0.32) exceeded the measured-PEEP estimate (-0.05); result -0.24 (-0.27 to -0.18); MIMIC-IV unchanged (-0.17).
